# Environment variables — JQC/PWI Management

Every SharePoint site and list reference in the app and the upload flow goes through these six **environment variables** (CLAUDE.md Section 10). They are already defined in the solution (`solution/JQCPWIManagement/src/environmentvariabledefinitions/`, generated by `solution/build.py`), so **you don't create them by hand**. You only give them values when you import the solution.

The solution ships with **no values**: no site URL, list ID or tenant ID is stored in the repo or the `.zip`.

## The variables

| Schema name | Display name in Power Apps | Type | Points to | Parent |
|---|---|---|---|---|
| `jp_SiteUrl` | JQC/PWI - SharePoint site | Data source: SharePoint **site** (`dataset`) | The site that holds the five JP_ lists and libraries | — |
| `jp_ListEmployees` | JQC/PWI - JP_Employees list | Data source: SharePoint **list** (`table`) | `JP_Employees` | `jp_SiteUrl` |
| `jp_LibDocuments` | JQC/PWI - JP_Documents library | Data source: SharePoint **list** (`table`) | `JP_Documents` | `jp_SiteUrl` |
| `jp_ListAssignments` | JQC/PWI - JP_Assignments list | Data source: SharePoint **list** (`table`) | `JP_Assignments` | `jp_SiteUrl` |
| `jp_LibSignoffs` | JQC/PWI - JP_SignoffRecords library | Data source: SharePoint **list** (`table`) | `JP_SignoffRecords` | `jp_SiteUrl` |
| `jp_ListSettings` | JQC/PWI - JP_Settings list | Data source: SharePoint **list** (`table`) | `JP_Settings` | `jp_SiteUrl` |

Notes:
- For the SharePoint connector, document libraries count as lists, so the two libraries are also `table` variables.
- The five list variables are **children** of `jp_SiteUrl`. In the import wizard you pick the site first, then each list is chosen from that site.
- **Values:**
  - The site variable stores the site URL, for example `https://contoso.sharepoint.com/sites/JQCPWI` (fictional).
  - A list variable stores the list's **ID (a GUID)**. `provisioning/Create-Lists.ps1` prints all five IDs when it finishes.
  - Never commit real values.

## How the values get set

### When you import the solution (normal path)
1. Run `provisioning/Create-Lists.ps1` against the target site first, so the lists exist.
2. **make.powerapps.com** → choose the target environment (top right) → **Solutions** → **Import solution** → **Browse** → pick `JQCPWIManagement_<version>_unmanaged.zip` from `solution/dist/` → **Next**.
3. **Connections:** if the wizard asks for SharePoint or Office 365 Users connections, pick an existing one or create one.
4. **Environment variables:** the wizard lists the six JQC/PWI variables.
   - **JQC/PWI - SharePoint site:** pick the site, or paste its URL.
   - Each **list** variable: pick the matching list from that site, for example **JP_Employees** for *JQC/PWI - JP_Employees list*.
5. **Import.**

### Changing a value later (for example, moving to another site)
- Open **Solutions** → **Default Solution** → **Environment variables** → open the variable.
- Under **Current value**, choose the new site or list → **Save**.
- Then reopen the app in Studio, or republish it, so the app picks up the change.
- Don't edit the **Default value**. The solution deliberately has none.

### Moving to another environment (test → production)
Import the same `.zip` there. The wizard asks for that environment's values, so nothing changes in the source.

## Requirements

- The target environment must have **Dataverse enabled**. Solutions, environment variables and connection references are stored there.
  - The app's data still lives only in SharePoint, so this is consistent with the "no Dataverse" rule (SPEC.md A-24).
  - Most environments, including the default one, already have Dataverse.
- The importing user needs the **Environment Maker** (or System Customizer) role in that environment, and access to the SharePoint site.
